对当前仓库执行全团并行评审。

## 步骤

1. 先读 `.opencode/KNOWN_BUGS.md`，把已知缺陷作为基线，核对它们是否仍然存在（行号可能已漂移）。

2. 并行拉起以下 agent（task 工具）：

| 领域 | agent | 关注点 |
|---|---|---|
| 架构 | `arch` | D1–D8 契约一致性、C1/C2/C3/C5/C6 落地、模块边界 |
| 引擎层 | `engine` | 状态机、ExecCompat、进程守护、快照安装 |
| 界面层 | `ui` | SSE 生命周期与配额、Compose 状态、KeyVault |
| 原生构建 | `native` | 16KB 对齐、零动态依赖、依赖锁 |
| 快照构建 | `snapshot` | 体积预算、manifest C1、版本锁定 |
| 发布运维 | `release` | 四道 gate + 编译断言是否真有牙 |
| 质量 | `qa` | 门禁盲区、测试缺口、可复现性 |
| 安全 | `security` | 权限面、凭据生命周期、网络与原生库风险 |

3. 等待全部返回后汇总为报告：

```markdown
# 安卓全流程专家团体检报告

## 一句话结论
<能否编译 / 主要风险 / 是否可发布>

## P0 阻断（必须立即修）
| # | 文件:行号 | 问题 | 责任 agent |

## P1 功能损坏
## P2 边界 / P3 质量
## 门禁盲区
## 安全风险
## 修复顺序建议
```

## 纪律
- 只报告，不修改代码
- 所有结论必须带 `文件:行号`
- KNOWN_BUGS.md 已有的标注「已知」而非新发现
- agent 结论冲突时以能给出代码证据的一方为准，标注分歧

用户附加要求：$ARGUMENTS
