## 1. 文档定位

本项目把 OpenCode（anomalyco/opencode，Bun 单文件二进制）打包为安卓 APP：UI 层 Kotlin/Compose，引擎层为「Ubuntu 24.04 arm64 rootfs + opencode linux-arm64」快照，经 proot（可选 qemu-user 降级）跑 `opencode serve` 绑定 `127.0.0.1`，UI 经 REST/SSE 驱动。两种引擎模式（None 远程 / Ubuntu 本地）共用同一 EngineClient。

双层结构与数据流以 `README.md` §2 架构图为准，本总纲不重复绘图，只定稿决策与契约。

## 2. D1–D8 技术决策定稿表

> 结论标记：**【确认】** = 维持原方案；**【修订】** = 在原方案基础上收敛/补充，理由附后。

| # | 决策项 | 定稿结论 | 状态 | 修订/确认理由 |
|---|--------|----------|------|---------------|
| D1 | Linux 环境方案 | **proot**（Termux 适配 fork，GPL-2.0+），否决 chroot / AVF VM / 依赖 Termux | 确认 | 免 root、单 APK 自包含、社区 5 周+ 日用实证；glibc 官方二进制无法跑 bionic（issue #21043），完整 rootfs 是唯一成熟路径；AVF 仅限 Pixel 8+/16GB，覆盖率不可接受 |
| D2 | opencode 运行形态 | **`opencode serve` 无头模式**，UI 走 HTTP/SSE；TUI 仅作为 M1 终端形态的前台进程直跑入口 | 确认 | serve 是官方一等公民 API（SDK/OpenAPI 均由其生成）；无头不吃 TUI 渲染内存；TUI 兜底走 D6 终端形态，二者并存不冲突 |
| D3 | 快照分发 | **full/lite 双变体**；full 内嵌 assets，lite 首启按 manifest 下载；**压缩包体积硬门禁 ≤ 160MB，解压后 ≤ 320MB，CI 超限即 fail** | 修订 | 原方案正文出现「150–250MB」与「120–160MB」两种口径，矛盾。定稿统一为 120–160MB 预算、160MB 为 CI 硬门禁（超限先裁剪工具链，禁止静默放行）。门禁落点：release.yml `job_snapshot` 增加体积检查 step |
| D4 | 宿主侧二进制存放 | proot/qemu 以 `lib*.so` 命名入 `jniLibs/arm64-v8a/`，运行时从 `nativeLibraryDir` 执行；**必须显式 `extractNativeLibs=true`（AGP: `useLegacyPackaging=true`）；v1 不引入 busybox** | 修订 | ① 关键补充：minSdk≥23 时 AGP 默认 `useLegacyPackaging=false`，库不解压进 `nativeLibraryDir`，`ProcessBuilder` 将无法 exec libproot.so —— 原 D4 未写明，**漏配即全链路不可用**，列入 native-builder 与 release-ops 的双重检查项。② 原 D4 提及 busybox，v1 rootfs 自带完整工具链、宿主侧无 shell 需求，砍掉该编译对象，交付清单收敛为两库（见 §3.3） |
| D5 | noexec 兜底 | **ExecCompat 运行时探测 + 降级**：DIRECT（直跑 proot）/ QEMU（proot `-q libqemu_aarch64.so`），探测结果落盘缓存；**新增第二级「启动自愈」**（探测协议详见 §3.2） | 修订 | 原三层策略缺少「探测误判后如何自愈」：DIRECT 探测通过但 proot 运行时因 ROM 差异仍失败的场景无出路。定稿补 L2 自愈（健康检查失败 + 日志特征 → 清缓存强制 QEMU 重试一次），兜底终态为 FAILED 诊断报告 + None 模式引导 |
| D6 | 终端形态实现 | **ConnectBot terminal 库 fork（Apache-2.0）** 直跑 proot bash → `opencode` TUI；不引入 GPL Termux 库 | 确认 | TUI 是官方全功能兜底界面；协议无传染；M1 以此作为引擎链路最短验证路径 |
| D7 | 16KB page | 自编译 proot/qemu 全部 `-Wl,-z,max-page-size=16384`，CI readelf 校验 LOAD 段 align ≥ 16384，16KB 模拟器进 CI 冒烟；**qemu-user 必须启用 TARGET_PAGE_BITS_VARY（运行时适配 16KB host page）；16KB 设备上允许 guest 4KB 对齐二进制直接走 QEMU 模式，不做 guest 侧重编译** | 修订 | ① qemu-user 默认 TARGET_PAGE_BITS=12（4KB），在 16KB host page 上 MAP_FIXED/mmap offset 对不上，必须编译期启用页位宽可变（Termux 2024+ 配方已含），列为 native-builder 硬性要求与 M0 实验验证项。② 16KB 设备的 guest glibc 加载风险收敛路径定为 QEMU 模式（qemu 自管 guest 映射），绝不尝试 patch opencode 二进制 |
| D8 | 保活 | Foreground Service（`dataSync`）+ WakeLock（上限 6h，可配）+ 幻影进程引导页 + 电池优化豁免引导；**崩溃守护退避 30s→1m→2m，10 分钟窗内 3 连败进 FAILED 终态** | 确认 | 幻影杀手无法纯代码规避，引导页 + 自动重启是完整对策；退避参数与骨架 `EngineService.kt` 一致，予以定稿冻结 |

**决策冻结规则**：D1–D8 即刻冻结。M0 实验只允许对 D5（探测结论）与 D7（qemu 页宽）产出「参数级」修正（如探测超时阈值、日志特征串），不允许推翻决策方向；推翻需主理人终裁。

## 3. 层间接口契约（原文引用区）

> 本节为下游成员直接引用的契约原文。字段名、路径、枚举值均为**定稿**，实现必须逐字一致。

### 3.1 C1 — 快照 manifest schema

**发布侧 `manifest.json`**（CI 产出，与 tar.gz 同发于 GitHub Release，full 变体同入 assets）：

```json
{
  "schemaVersion": 1,
  "snapshotVersion": "20261007-oc1.18.34",
  "ocVersion": "1.18.34",
  "ubuntuBase": "24.04.2",
  "file": "oc-ubuntu-arm64.tar.gz",
  "sha256": "<64 位小写 hex，压缩包全文哈希>",
  "size": 152000000,
  "format": "tar.gz",
  "layout": "rootfs-at-tar-root",
  "excludes": ["./workspace", "./root/.local/share/opencode"],
  "minAppVersion": "1.0.0"
}
```

字段级规则：

| 字段 | 类型 | 规则 |
|------|------|------|
| `schemaVersion` | int | 固定 1。App 读到非 1 值 → 拒绝安装并提示升级 App |
| `snapshotVersion` | string | 格式 `YYYYMMDD-oc<ocVersion>`。**比较规则：纯字典序**（日期前缀保证单调），App 禁止解析内部结构 |
| `ocVersion` | string | 快照内锁定的 opencode 版本，需与 `GET /global/health` 返回的 version 前缀一致 |
| `sha256` | string | 64 位小写 hex。App 安装时流式校验，不匹配即整目录回滚 |
| `size` | number | 压缩包精确字节数。lite 变体用于下载进度与磁盘预检（要求可用空间 ≥ size + 解压后体积，后者以 `size × 2.1` 估算） |
| `excludes` | string[] | 打包剔除清单，与 App 端升级搬移清单（§3.5 保留目录）互为镜像，两端必须同步维护 |
| `minAppVersion` | string | semver。lite 变体下载前校验，不满足则阻断并引导升级 App |
| `ubuntuBase` / `file` / `format` / `layout` | string | 诊断与追溯字段，App 不做逻辑判断 |

**App 端 `.snapshot-meta.json`**（落位于 `{filesDir}/rootfs/.snapshot-meta.json`，幂等唯一事实来源）：

```json
{
  "schemaVersion": 1,
  "snapshotVersion": "20261007-oc1.18.34",
  "ocVersion": "1.18.34",
  "sha256": "<实际校验通过的哈希>",
  "state": "ready",
  "installedAt": "2026-10-07T12:00:00Z"
}
```

- `state` 枚举定稿：**`ready`** = 安装完成且校验通过；**`extracting`** = 解压中；**`failed`** = 失败。**任何非 `ready` 值一律视为未安装，下次启动整目录删除重装**。
- 写入时序：原子 rename rootfs 目录之后才允许写 meta；meta 写入失败按未安装处理。

### 3.2 C2 — ExecMode 探测协议

枚举：`ExecMode { DIRECT, QEMU }`。

**L1 探测（决定初始模式，结果落盘 `{filesDir}/.exec-mode`）**：

| 步骤 | 操作 | 判定 |
|------|------|------|
| 1 | 取 `{rootfs}/usr/bin/env`；不存在 → 直接 QEMU 并记录诊断 | — |
| 2 | `File.setExecutable(true)` | — |
| 3 | `ProcessBuilder(env.absolutePath, "--version")`，5 秒超时 | — |
| 4a | 退出码 = 0 | **DIRECT** |
| 4b | 异常链含 EACCES / "Permission denied"（SELinux execute 拦截） | **QEMU** |
| 4c | 其他异常（超时、崩溃、非 0 退出） | **QEMU**（安全兜底）+ 诊断记录 |

- 探测缓存：`.exec-mode` 内容为模式名字符串。设置页提供「重新探测」入口（清缓存重跑），ROM 升级后用户可自愈。
- 等价性依据：proot 经 PTRACE_TRACEME + execve，SELinux 对 execve 的拦截先于 ptrace，故 host 侧探测结果与 proot 内一致（M0 真机验证项，见 §4）。

**L2 启动自愈（新增，覆盖 L1 误判）**：

1. 引擎以 L1 结论启动；健康检查 60s 超时且进程存活或退出时，读取 engine.log 尾部 4KB；
2. 若含以下任一特征串（大小写敏感，native-builder 可扩充并登记）：`Permission denied`、`Exec format error`、`failed to load`、`error while loading shared libraries` → 判定 L1 误判；
3. 处置：删除 `.exec-mode` 缓存 → 强制以 QEMU 模式重试一次 → 仍失败进 FAILED 终态。

**FAILED 终态输出**（诊断报告，UI 弹窗 + engine.log 落盘）：SELinux 上下文（`/proc/self/attr/current` 可读值）、内核版本、设备 page size（`getconf PAGESIZE` 宿主侧）、ExecMode 尝试历史、engine.log 尾部。**报告末尾固定附 None（远程）模式引导文案**。

### 3.3 C3 — 原生库契约

| 项 | libproot.so | libqemu_aarch64.so |
|----|-------------|--------------------|
| ABI | arm64-v8a（唯一，`abiFilters = ["arm64-v8a"]`） | arm64-v8a |
| 上游 | Termux proot 适配 fork（GPL-2.0+） | qemu-user-static，仅 aarch64 guest |
| 链接 | 静态优先（`-static`）；如受上游限制动态链 bionic，需 CI 断言零额外 .so 依赖 | 强制 `--static` |
| NDK 目标 | `aarch64-linux-android26-clang`（API 26 = minSdk） | 同左（meson 构建，编译时长预算 ~20min） |
| 链接器 flags | `-Wl,-z,max-page-size=16384` | 同左 |
| qemu 特殊要求 | — | **TARGET_PAGE_BITS_VARY 必须启用**（运行时适配 4KB/16KB host page） |
| 交付路径 | `app/src/main/jniLibs/arm64-v8a/libproot.so` | `app/src/main/jniLibs/arm64-v8a/libqemu_aarch64.so` |

CI 硬性校验（release-ops 与 native-builder 双方都要执行，任一方失败即阻断发布）：

1. `llvm-readelf -l` → 所有 `LOAD` 段 `Align` ≥ `0x4000`（16384）；
2. 文件名以 `lib` 开头、`.so` 结尾（jniLibs 打包约束）；
3. 16KB 模拟器冒烟：`libproot.so --version` 直接可执行退出码 0；
4. APK manifest 断言 `android:extractNativeLibs="true"`（等效 gradle `packaging { jniLibs { useLegacyPackaging = true } }`）——**此项漏配 = 库不解压 = ProcessBuilder 不可执行，属发布阻断级检查**。

**proot `-q` 参数约定**：QEMU 模式下传给 proot 的 qemu 路径必须是**宿主侧绝对路径**（`{nativeLibraryDir}/libqemu_aarch64.so`），proot 不做该参数的 guest 路径翻译。

### 3.4 C4 — EngineClient ↔ opencode serve 端点契约

**baseUrl 规则**：Ubuntu 模式 = `http://127.0.0.1:{port}`；None 模式 = 用户配置的 `http(s)://host[:port]`。二者共用同一客户端实现。

**认证契约**：

- 方案：HTTP **Basic Auth**。用户名固定 `opencode`，密码 = 环境变量 `OPENCODE_SERVER_PASSWORD` 的值。
- 密码生成：App 每次引擎启动时随机生成 **32 位小写 hex**（SecureRandom），仅经 `EngineHandle{baseUrl, password, ocVersion}` 内存传递给 UI 层，**不落盘**。
- 密码生命周期 = 引擎进程生命周期，重启引擎即轮换。
- None 模式：用户在设置页填远程地址 + 可选用户名/密码，App 同样走 Basic Auth；明文 http 地址需 UI 警示。

**端点清单**（路径为稳定契约；请求/响应 body 字段一律以启动时 `GET /doc` 返回的 OpenAPI 3.1 为准，客户端**禁止硬编码 body schema**——这是版本漂移对策的一部分）：

| 端点 | 方法 | 用途 | 使用阶段 |
|------|------|------|----------|
| `/global/health` | GET | 就绪与健康检查，返回含 `{healthy, version}`；version 即 ocVersion | M1 起，引擎自检 + None 连通测试 |
| `/doc` | GET | OpenAPI 3.1 spec；客户端启动时拉取校验端点存在性，缺失端点则禁用对应 UI 功能 | M1 起 |
| `/session` | GET / POST | 会话列表 / 创建会话 | M2 |
| `/session/:id` | GET / PATCH / DELETE | 会话详情 / 更名 / 删除 | M2 |
| `/session/:id/message` | GET / POST | 消息历史 / 同步发送 prompt | M2 |
| `/session/:id/prompt_async` | POST | 异步发送 prompt（推荐路径，UI 不阻塞），结果经 SSE 回流 | M2 |
| `/session/:id/abort` | POST | 中断当前 agent 运行 | M2 |
| `/event` | GET（SSE） | 全局事件流：流式输出、权限请求、会话状态 | M2 |
| `/session/:id/permissions/:permissionID` | POST | 权限审批回复（once / always / reject，语义以 /doc 为准） | M2 |
| `/session/:id/diff` | GET | 会话内文件变更 diff | M3 |
| `/file`、`/find` | GET | 文件读取 / 搜索（工作区） | M3 |
| `/config` | GET / PATCH | 引擎侧配置读写 | M3 |

**SSE 事件约定**：客户端必须处理的最低事件集合 = 消息片段更新（流式渲染）、权限请求（触发原生审批弹窗）、会话错误；**未知事件类型一律忽略不崩溃**。同一时刻允许 ≤ 2 个 SSE 订阅（终端桥 + 原生 UI），`/event` 为全局广播、无互斥；断线按指数退避重连（1s 起，上限 30s），重连成功后客户端需重建会话状态。

### 3.5 C5 — 目录与 bind 契约

**宿主侧（Android 路径，`<pkg>` 为 applicationId）**：

| 路径 | 角色 |
|------|------|
| `/data/data/<pkg>/files/rootfs` | 快照解压根（proot `-r` 参数） |
| `/data/data/<pkg>/files/rootfs/.snapshot-meta.json` | 幂等标记（C1） |
| `/data/data/<pkg>/files/oc-auth/` | **配置注入目录**（bind 到 guest `/root/.config/opencode`） |
| `/data/data/<pkg>/files/oc-auth/auth.json` | Provider Key 注入文件，权限 600 |
| `/data/data/<pkg>/files/oc-auth/opencode.json` | 引擎配置（`autoupdate=false`、`share=disabled` 等），App 生成 |
| `/data/data/<pkg>/cache` | `PROOT_TMP_DIR`（宿主侧环境变量，不进 guest） |
| `/storage/emulated/0/Android/data/<pkg>/files/workspace` | 工作区（外部私有目录，免存储权限，bind 到 guest `/workspace`） |
| `{nativeLibraryDir}` | libproot.so / libqemu_aarch64.so 唯一可执行区 |

**guest 侧**：

| 路径 | 角色 |
|------|------|
| `/usr/local/bin/opencode` | 官方单文件二进制（chmod 755） |
| `/root/.local/share/opencode/opencode.db` | SQLite 会话库，**升级快照时保留** |
| `/workspace` | bind 挂载点 |
| `/root/.config/opencode/` | bind 注入点（被宿主 oc-auth 遮蔽） |

**bind 挂载清单（proot `-b`，顺序无关但内容定死）**：`/dev`、`/proc`、`/sys`（原样）、`{workspace}:/workspace`、`{authDir}:/root/.config/opencode`。

**快照升级保留目录**（与 manifest.excludes 互为镜像，升级搬移仅限以下两项）：
1. `root/.local/share/opencode`（会话库）
2. `root/.config/opencode`（当前由 bind 遮蔽，搬移仅为防御性兼容）

**配置唯一写入者原则（冲突消解定稿）**：原方案同时存在「快照内预置 opencode.json 模板」与「authDir bind 遮蔽该路径」，二者冲突。定稿：**App 是 auth.json 与 opencode.json 的唯一写入者，均写入 oc-auth 注入目录**；快照内 `/root/.config/opencode` 下的模板文件仅作离线参考、运行期不生效。snapshot-builder 无需修改（保留无害），engine-layer 必须实现注入目录写入。

### 3.6 C6 — 启动参数与环境变量契约

**端口分配**：`4096..4160` 范围内以 `ServerSocket` 探测首个空闲口（探测与占用存在固有竞态，可接受——绑定失败由健康检查超时兜底重启）。

**proot 命令模板**（骨架 `EngineService.buildProotCommand()` 为权威实现参考）：

```
DIRECT: {nativeDir}/libproot.so --kill-on-exit -0 -w /root -r {rootfs} \
          -b /dev -b /proc -b /sys \
          -b {workspace}:/workspace -b {authDir}:/root/.config/opencode \
          /usr/bin/env -i {env...} opencode serve --hostname 127.0.0.1 --port {port}

QEMU:   同上，在 -w /root 之后追加 -q {nativeDir}/libqemu_aarch64.so
```

**guest 环境变量集（`env -i` 全量注入，缺一不可）**：

| 变量 | 值 |
|------|----|
| `HOME` | `/root` |
| `LANG` / `LC_ALL` | `C.UTF-8`（中文乱码修复，社区实测必须） |
| `PATH` | `/usr/local/bin:/usr/bin:/bin` |
| `XDG_DATA_HOME` | `/root/.local/share` |
| `HTTP_PROXY` / `HTTPS_PROXY` | 用户配置代理（可为空） |
| `NO_PROXY` | `127.0.0.1,localhost` |
| `OPENCODE_SERVER_PASSWORD` | 本轮随机 32 位 hex |

**健康检查**：`GET /global/health`，指数退避 300ms 起、上限 2s，总超时 60s；超时触发 L2 自愈（§3.2）。

## 4. M0–M4 里程碑与逐项验收清单

## 5. 下游阶段输入摘要

### 5.1 → snapshot-builder（快照构建规格要点）

- 权威脚本：`code/build-snapshot.sh`，在 **arm64 runner 原生 chroot**（不用 qemu）。
- 锁版本：`OC_VERSION`（默认 1.18.34，与 release.yml env 同步）、`UBUNTU_BASE_VER=24.04.2`（cdimage 直链防漂移）。
- 工具链清单（骨架 `PKGS`）维持：git curl wget ca-certificates locales ripgrep fd-find jq unzip zip less procps openssh-client tmux。
- 打包参数冻结：`--numeric-owner --sort=name --mtime='UTC 2026-01-01'`（内容寻址可复现）；`EXCLUDE_TAR = ./workspace, ./root/.local/share/opencode`（与 manifest.excludes 镜像）。
- 必产出：`oc-ubuntu-arm64.tar.gz` + `manifest.json`（**按 §3.1 schema，需在骨架基础上补 `schemaVersion`、`excludes`、`minAppVersion` 三字段**）。
- 冒烟：chroot 内 `/usr/local/bin/opencode --version` 失败即构建作废。
- **新增体积门禁：tar.gz > 160MB 直接 fail**（先裁工具链，禁止静默放行）。

### 5.2 → native-builder（NDK-16KB 目标）

- 交付物仅两个：`libproot.so`（Termux fork，静态优先）与 `libqemu_aarch64.so`（--static，仅 aarch64 guest）。**v1 不做 busybox**。
- 编译：NDK `aarch64-linux-android26-clang`；LDFLAGS/CFLAGS 含 `-Wl,-z,max-page-size=16384`。
- **qemu 必须启用 TARGET_PAGE_BITS_VARY**（否则 16KB host page 上 MAP_FIXED 失败）；参考 Termux packages qemu-user 构建配方。
- 构建脚本需落位 `native/build-qemu-user-static.sh`（当前 release.yml 引用了该路径但文件缺失，由你交付）。
- 交付自检按 §3.3 四项执行，任何一项不过不得合入。

### 5.3 → engine-layer（引擎接口要点）

- ExecCompat 按 §3.2 实现（L1 探测 + `.exec-mode` 缓存 + L2 自愈 + FAILED 诊断报告）；日志特征串可扩充但需登记。
- proot 命令构造、端口分配（4096–4160）、环境变量集、健康检查参数全部按 §3.6；骨架 `EngineService.kt` 为权威参考。
- 目录契约按 §3.5；**配置注入目录（oc-auth）必须由 App 写入 auth.json + opencode.json**（唯一写入者原则）。
- 状态机：`STOPPED → INSTALLING → STARTING → READY / FAILED`，EngineHandle{baseUrl, password, ocVersion} 为 UI 层唯一对接句柄。
- 已知骨架笔误需修复：`SnapshotInstaller.kt` L102 `md.update` 应为 `digest.update`。

### 5.4 → ui-layer（UI 端点清单）

- 全部请求走 §3.4 端点清单 + Basic Auth（`opencode` + EngineHandle.password）。
- body schema 一律以 `GET /doc` 动态获取，禁止硬编码。
- M1 终端形态：ConnectBot 库 fork proot bash 直跑 TUI，快捷键条 Esc/Tab/Ctrl/Ctrl+D。
- M2 必做：SSE 渲染 + 权限审批弹窗 + Provider Key 管理（Keystore）+ 代理设置 + None 模式设置页（地址/用户名/密码/连通测试按钮）。
- 安全红线：引擎地址只可指向 127.0.0.1 或用户显式配置的远程；明文 http 需警示；密码不落盘、不进日志。

### 5.5 → release-ops（CI 拓扑要点)

- 双 job：`job_snapshot`（**ubuntu-24.04-arm runner**）→ artifact → `job_android`（x86）编原生库 + 双变体签名 APK → GitHub Release。
- tag 触发 `v*`；snapshotVersion 内嵌 tag 日期 + OC_VERSION。
- 发布产物清单（缺一不可）：full APK、lite APK、`oc-ubuntu-arm64.tar.gz`、`manifest.json`。
- 新增 CI gate：① 16KB 对齐校验（§3.3）；② 快照体积 ≤160MB；③ manifest schemaVersion==1 断言；④ extractNativeLibs 断言。

### 5.6 → device-validator（真机验收标准）

- 真机矩阵：Android 11/13/15 各 ≥1 台 + 16KB flag 模拟器；覆盖 4GB 与 8GB 内存档（4GB 档仅验证 None 模式可用性 + 内存预警）。
- 执行 M0 全部 6 项与 M1/M2 的真机项；M4 性能口径（45s 冷启动、300MB 空载、0.5% 崩溃率）由你出最终报告。
- 幻影进程场景专项：Android 12+ 未解除限制时复现引擎被杀 → 引导页 → 解除后 24h 存活测试。
