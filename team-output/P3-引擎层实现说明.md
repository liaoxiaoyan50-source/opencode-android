```

  │                                            │ ③ install 成功 + 注入就绪
```

## 2. ExecCompat（P1 §3.2；P2b §5-3、§6）

### 2.1 L1 探测决策表（runProbe L136-177）

| 步骤 | 操作 | 判定 | 落点 |
|------|------|------|------|
| 1 | 取 `{rootfs}/usr/bin/env` | 不存在 → QEMU + 诊断「快照异常」 | L138-141 |
| 2 | `File.setExecutable(true)` | 抛异常 → QEMU | L144-148 |
| 3 | `ProcessBuilder(env --version)`，5s 超时窗 | start 抛异常 → 按 4b/4c 分流；超时 → 4c | L150-163、L166-167 |
| 4a | 退出码 = 0 | **DIRECT** | L168-169 |
| 4b | 异常链（含 cause 最深 5 层）含 EACCES/"Permission denied" | **QEMU**（SELinux execute 拦截） | L154-157 + isPermissionDenied L180-184 |
| 4c | 超时/非 0 退出/其他异常 | **QEMU**（安全兜底）+ 诊断 | L160-162、L170-172 |

等价性依据：SELinux 对 execve 的拦截先于 proot 的 ptrace，host 侧探测与 proot 内行为等价（detect() 注释 L88-89）。

### 2.2 `.exec-mode` 缓存读写时序

- **读**：detect() L92-97，由 bootSequence 步骤 4 调用（L305），每次引擎启动仅一次；命中即零探测开销；内容非法（valueOf 失败）视为无缓存并删除重探（L96）。
- **写**：runProbe 出结论后 writeDiag（`.exec-mode.diag`，带时间戳）L99 + `cache.writeText` L100；落盘失败不阻断启动（runCatching）。
- **清**：① 设置页「重新探测」reprobe L105-108（ROM 升级后用户自愈）；② L2 自愈处置 clearCache L111（触发点 L366）。
- 诊断回读：readDiag L114-115，FAILED 报告引用（L619）。

## 3. proot 命令两式（buildProotCommand L490-522）

样例变量：`{nativeDir}`=applicationInfo.nativeLibraryDir（L239，唯一可执行区，D4）；`{rootfs}`={filesDir}/rootfs（L237）；`{workspace}`={getExternalFilesDir(null)}/workspace（L238，外部私有免存储权限）；`{authDir}`={filesDir}/oc-auth（L240）；`{port}`=4096..4160 探测值；`{pw}`=本轮 32 位 hex 口令。

**DIRECT 式**：

```
{nativeDir}/libproot.so --kill-on-exit -0 -w /root \
  -r {rootfs} \
  -b /dev -b /proc -b /sys \
  -b {workspace}:/workspace \
  -b {authDir}:/root/.config/opencode \
  /usr/bin/env -i \
    HOME=/root  LANG=C.UTF-8 LC_ALL=C.UTF-8 \
    PATH=/usr/local/bin:/usr/bin:/bin  XDG_DATA_HOME=/root/.local/share \
    HTTP_PROXY={代理} HTTPS_PROXY={代理} NO_PROXY=127.0.0.1,localhost \
    OPENCODE_SERVER_PASSWORD={pw} \
  opencode serve --hostname 127.0.0.1 --port {port}
```

**QEMU 式**：同上，在 `-w /root` 之后插入 `-q {nativeDir}/libqemu_aarch64.so`（L519-520）。`-q` 必须为**宿主侧绝对路径**，proot 不做该参数的 guest 路径翻译（P1 §3.3 / P2b §5-2）；两库 NEEDED=0 静态产物，无需 LD_LIBRARY_PATH（P2b §5-1）。

宿主侧进程环境：`PROOT_TMP_DIR={cacheDir}/proot` 经 ProcessBuilder.environment() 注入、不进 guest（startEngineProcess L404-408；目录就绪见 bootSequence 步骤 3 L301-302）。落点取 cache 的 proot 子目录而非 cache 根，防 L2 清缓存误删 lite 下载产物——与 P1 §3.5「{pkg}/cache」的偏差属子目录级细化，代码注释 L241-243 所指请终裁点在此定稿口径。

**bind 清单**（L505-509，P1 §3.5 C5 内容定死）：`/dev`、`/proc`、`/sys` 原样；`{workspace}:/workspace` 工作区；`{authDir}:/root/.config/opencode` 配置注入点（§5）。

**env -i 环境变量集**（L494-503，P1 §3.6 表逐项）：HOME=/root；LANG/LC_ALL=C.UTF-8（中文乱码修复）；PATH=/usr/local/bin:/usr/bin:/bin；XDG_DATA_HOME=/root/.local/share（会话库锚点）；HTTP_PROXY/HTTPS_PROXY=Settings.proxy 用户配置可为空（L203）；NO_PROXY=127.0.0.1,localhost（本机回调不走代理）；OPENCODE_SERVER_PASSWORD={pw}。

## 4. 认证与端口

**Basic Auth 生成**（P1 §3.4 逐字落地）：
- 生成：bootSequence 步骤 5 `randomToken(32)`（L308 → 实现 L762-763）：SecureRandom 逐字符取 HEX 池 `0123456789abcdef`（L801），得 32 位小写 hex。
- 不落盘：仅存内存字段 enginePassword（L232）；经 guest 环境变量 OPENCODE_SERVER_PASSWORD 传给 serve（L502，仅进程环境）；engine.log 分隔行明示不记录口令（L564）。
- 轮换：每次 bootSequence 重新生成 = 重启引擎即轮换；生命周期 = 引擎进程生命周期。
- 校验侧：引擎健康检查 `Credentials.basic("opencode", enginePassword)`（L423），用户名固定 opencode。

**EngineHandle{baseUrl, password, ocVersion} 传递路径**（L78）：READY 时 `handle.tryEmit(EngineHandle("http://127.0.0.1:{port}", enginePassword, version))`（L350）→ MutableSharedFlow(replay=1)（L225）→ ui-layer 订阅即得最近一次句柄 → 据此构造 EngineClient。ocVersion 取自 /global/health body 的 version 字段（L428）；与 manifest.ocVersion 前缀比对仅告警不阻断（warnVersionDrift L653-662）。

**端口 4096-4160 探测**（allocatePort L754-759）：PORT_MIN/MAX=4096/4160（L804-805）；对每口以 `ServerSocket().bind(127.0.0.1:p)` 成功且立即 close 判定空闲，firstOrNull 取首个；全占用抛 IllegalStateException。每轮守护循环重新探测（L331）。探测-占用 TOCTOU 竞态 P1 §7-5 定稿接受：绑定失败由健康检查 60s 超时兜底触发守护重启（L330、L752-753）。

## 5. oc-auth 注入（P1 §3.5 配置唯一写入者原则）

**写入时序**（bootSequence 步骤 2 → writeOcAuth L535-541，每次引擎启动前执行，失败即 FAILED L297-298）：
1. `authDir.mkdirs()` —— {filesDir}/oc-auth；
2. `auth.json` ← Settings.authJson(context)：ui-layer 在 startEngine **之前**设置 `Settings.authJsonProvider` 内存回调（L201，返回 Keystore 解密后的 auth.json 文本），引擎层自身不持久化明文、不进日志；未配置 Provider 默认 "{}"（L205-206）；
3. `opencode.json` ← 固定串 `{"autoupdate": false, "share": "disabled"}`（快照锁版禁自更新 + 禁分享，L539）；
4. `restrictOwner600(auth.json)`（L544-554）：POSIX setPosixFilePermissions(owner rw-) 优先，异常退化 File API（setReadable/Writable(true, onlyOwner)），等效权限 600。

**唯一写入者原则**：App（引擎层）是 auth.json 与 opencode.json 的唯一写入者，均写入 oc-auth 注入目录；该目录整体 bind 遮蔽 guest /root/.config/opencode（§3 bind 表），是运行期配置唯一生效来源；快照内 `/root/.config/opencode` 模板文件仅离线参考、不生效（P1 §3.5 定稿）。SnapshotInstaller 升级搬移仍防御性保留 root/.config/opencode（SnapshotInstaller L141，P1 §3.5 保留目录条款），与唯一写入者不冲突——保留目录运行期被 bind 遮蔽。

## 7. 移交清单

### 7.1 → ui-layer 对接说明

- **句柄与生命周期**：`EngineService.start(context)/stop(context)`（L822-825）拉停引擎；订阅 `state: StateFlow<EngineState>`（L223）渲染状态卡；订阅 `handle: SharedFlow(replay=1)`（L225）——任意时刻订阅可得最近句柄。EngineHandle 三字段：baseUrl=`http://127.0.0.1:{port}`；password=本轮口令（生命周期=引擎进程、重启轮换、不落盘不进日志，**勿跨引擎重启缓存旧值**）；ocVersion=健康检查返回版本。
- **REST 对接**：端点按 P1 §3.4 清单；body schema 一律 `GET /doc` 动态获取，禁止硬编码；全部请求带 Basic Auth（用户名固定 `opencode`，密码=handle.password）。
- **SSE /event**：最低事件集=消息片段/权限请求/会话错误，未知事件忽略不崩溃；≤2 订阅（终端桥+原生 UI）；断线退避 1s→30s，重连成功后重建会话状态（P1 §3.4）。
- **权限弹窗触发来源**：/event 权限请求事件 → 原生审批弹窗（once/always/reject）→ POST `/session/:id/permissions/:permissionID`；引擎层只透传 HTTP/SSE，不解析事件。
- **注入点**：startEngine 前设置 `Settings.authJsonProvider`（L201）；代理写 SharedPreferences(engine_settings) 的 "proxy" 键（L203）；WakeLock 时长键 "wake_lock_hours"（L208）；设置页「重新探测」调 `ExecCompat.reprobe`（L105-108）；通知点击经 Class.forName 定位 `dev.opencode.mobile.ui.MainActivity`（companion MAIN_ACTIVITY L798，重构类名需同步；带 launcher 兜底 L731-736）。
- 引擎层不写 UI，只暴露上述 StateFlow/SharedFlow 与标准 HTTP/SSE 接口。
