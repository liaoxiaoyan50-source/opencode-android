## 2. EngineHandle 订阅与生命周期

**订阅面**：`EngineBus.handle`（replay=1，镜像 P3 L225）→ `AppController.client: StateFlow<EngineClient?>` 由 `combine(engineMode, remote, handleOrNull)` 产出——local 模式 handle 就绪（READY）才产出 `EngineClient(handle.baseUrl, "opencode", handle.password)`（P1 §3.4 用户名固定）；none 模式按用户配置产出同款客户端。handleOrNull 以 `onStart{emit(null)}` 解决 SharedFlow 无首发值时 combine 不发射的问题（none 模式不依赖引擎 READY）。

**引擎重启（password 轮换）的完整链路与 UI 表现**：
1. 引擎守护循环拉起新进程 → READY → handle 重发新句柄（旧 password 随引擎进程一起失效，P3 §7.1）；
2. combine 重算 → 新 EngineClient 实例替换旧实例 —— **旧 client 任何代码路径都拿不到**（勿缓存旧 password 的对策靠“实例替换”结构性保证，不做字符串级更新）；
3. `LaunchedEffect(client)` 触发 `ChatController.bind(new)`：取消旧 SSE 订阅（释放配额）→ 以新凭据重建订阅 → 全量重载会话列表与当前会话消息；
4. 过渡期 UI 表现：会话页状态卡显示“引擎启动中/引擎就绪”新状态；聊天输入框禁用（client 为 null 或正在重建时 `canPrompt=false`）；若旧 client 请求在轮换瞬间发出并返回 401，错误条提示“凭据已过期(引擎可能已重启)，等待新句柄…”，不弹任何凭据输入框（凭据由系统供给，P1 §3.4）。

**P3 需补的镜像转发（≤6 行，见 §8 终裁-1）**：EngineService.state/handle 是服务实例字段，前台服务实例 UI 无法直接引用；P3 在 `onCreate` 中调用 `EngineBus.attach(this)` 即完成镜像（本文件已含 attach 实现）。

## 3. SSE 渲染与重连状态重建

- **事件分类**（`parseEvent`）：type 精确匹配官方事件名优先（message.part.updated / permission.asked / session.error），语义关键词兜底抗漂移；都不中 → `Unknown`，仅 debug 日志，**忽略不崩溃**（P1 §3.4，M2-6）。字段全部宽松提取（sessionID/permissionID/part.text 等多候选键），载荷结构漂移不致崩溃。
- **渲染**：MessagePart 按 `partId`（退化 messageID）upsert 到消息流（part 快照语义）；PermissionAsked 入审批队列弹出原生弹窗；SessionError 显示错误条。/event 为全局广播，ChatController 一个订阅覆盖所有会话。
- **重连**（P1 §3.4 冻结参数）：断线（读失败/服务端关流/HTTP≠200）→ 指数退避 1s 起、×2、30s 封顶，连接成功即复位；每轮退避打 `Log.i(OpenCodeUI, "SSE 断线, Nms 后重连…")` —— **M2-4 的 logcat 观测点**（`adb logcat -s OpenCodeUI`）。30s 断网窗口内覆盖 1/2/4/8/16/30 多轮重试，恢复即连上。
- **状态重建**：连接成功回调 `onResync` → 重拉 `/session` 列表 + 当前会话 `/session/:id/message` 全量历史替换本地流式缓冲（幂等，首连也执行一次作为初始加载），实现“重连成功后重建会话状态”（P1 §3.4）。
- **配额**：`SseQuota` 全局 AtomicInteger 强制 ≤2（原生 UI 1 + 终端桥预留 1）；超发返回 `QUOTA_DENIED` 并在 UI 错误条提示。

## 4. Keystore 加密方案（M2-5）

- **Key 别名**：`opencode_master_aes`（AndroidKeyStore 内生成，不可导出）；**算法**：AES-256 / GCM / NoPadding；每次加密随机 12B IV。
- **密文格式**：`1|base64(iv)|base64(ciphertext)` 存普通 prefs `keystore_sealed` —— prefs XML 与文件系统/dumpsys 均无明文（M2-5）；版本前缀预留密钥轮换。解密失败返回 null 按未配置处理，不抛异常不泄痕迹。
- **存储项**：Provider API Key（用户输入的任意 provider id 槽位）与 None 模式远程密码（专用槽 `__remote__`）。
- **authJsonProvider 时序**（P3 §7.1）：MainActivity.onCreate **第一时间**设置 `Settings.authJsonProvider = { ctx -> KeyVault.buildAuthJson(ctx) }`（早于任何 `EngineService.start`）→ 引擎 bootSequence 写 oc-auth 时回调（P3 L535-541）→ 解密、按 opencode 上游格式组装 `{"<provider>":{"type":"api","key":"…"}}` → 引擎写 `oc-auth/auth.json`（600）→ 文本用后即弃。**UI 层自身不持久化明文**：明文只存在于回调调用栈内，不写文件、不进日志（KeyVault 无任何 Log 调用）。
- auth.json 内部 schema 未在 P1 冻结（P1 §3.5 仅冻结路径与权限），组装格式见 §8 终裁-2。

## 5. None 模式连通测试流程（M2-3）

1. 设置页 → 引擎模式选「None 远程」→ 填地址 `http(s)://host[:port]`、可选用户名（缺省 `opencode`，P1 §3.4）、密码；
2. 地址以 `http://` 开头 → 即时显示红色警示“明文 http 将暴露密码与会话内容”（P1 §3.4 明文警示）；
3. 点「连通测试」→ 构造临时 EngineClient（凭据同表单值）→ `GET /global/health`（Basic Auth）→ 成功显示 `✓ 连通成功 · opencode <version>`（version 取 body version 字段）；HTTP 非 200 / 网络异常分别显示错误码与原因（测试用的临时 client 不占用 SSE 名额）；
4. 点「保存」→ url/user 存 prefs `ui_settings`，密码经 KeyVault 密文落盘 → `remote` 流重发 → `client` 重建 → 聊天全流程可用（同一 EngineClient，零分支差异）。
