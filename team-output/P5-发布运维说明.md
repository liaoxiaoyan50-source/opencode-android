## 1. 双 job 拓扑与产物流

```
push tag v*（正式发布）            workflow_dispatch（冒烟/复跑，不发 Release，无 Secrets 时 debug 兜底）
     │                                        │
     ▼                                        ▼
┌─ job_snapshot（ubuntu-24.04-arm，原生 chroot 免 qemu，timeout 60min）─────────────┐
│ checkout → build-snapshot.sh（内置: 工具链/opencode 注入、--version 冒烟、       │
│   脚本侧体积门禁、manifest C1 自检）                                            │
│ → Gate ② 体积独立复核（160MiB=167772160 字节，同口径双保险）                     │
│ → Gate ③ manifest schemaVersion==1 + C1 字段完整性 + sha256/size 一致性          │
│   + manifest.ocVersion == OC_VERSION（防漂移断言）                              │
│ → tar 冒烟 → upload-artifact "snapshot"（oc-ubuntu-arm64.tar.gz + manifest.json）│
└──────────────────────────────────┬───────────────────────────────────────────────┘
                                   ▼ download-artifact
┌─ job_android（ubuntu-24.04 x86_64，timeout 120min）──────────────────────────────┐
│ 定位 NDK → apt(pkg-config/ninja) → SHA256 发布阻断前置（P2b §7-1）               │
│ → native/build-proot.sh + native/build-qemu-user-static.sh（脚本内自检:          │
│   AArch64 / NEEDED=0 / 对齐，产物落 app/src/main/jniLibs/arm64-v8a/）            │
│ → Gate ① check-page-align.sh 校验 jniLibs 两库（NDK llvm-readelf）              │
│ → 快照注入 app/src/full/assets/snapshot/ → gradle 双变体签名出包                 │
│ → Gate ④ APK manifest extractNativeLibs="true"（aapt2 dump xmltree）            │
│ → Gate ①b APK 内 .so 解包二次对齐校验 → 四件套 assert（含传输后 sha256 复核、     │
│   manifest.ocVersion 复核、debug 签名拒发）                                     │
│ → upload-artifact "apks"（full/lite APK；Release 发布已迁至 job_release，终裁 #4）│
└──────────────────────────────────┬───────────────────────────────────────────────┘
                                   ▼ download-artifact "apks"
┌─ job_smoke_16kb（ubuntu-latest x86+KVM，API 35 16k 镜像，timeout 45min）──────────┐
│ C3 第 3 项（P1 §3.3 终裁 #4，硬性校验）：sys.boot_completed 等待 → PAGESIZE=16384 │
│ 断言 → adb install full APK（artifact apks）→ adb shell libproot.so --version    │
│ 退出码 0；qemu 模式项待 device-validator 交付 native/ci-smoke-16kb.sh 后挂入      │
└──────────────────────────────────┬───────────────────────────────────────────────┘
                                   ▼ needs: [job_android, job_smoke_16kb]
┌─ job_release（ubuntu-latest，timeout 10min，contents:write）─────────────────────┐
│ download-artifact（snapshot + apks）→ softprops/action-gh-release@v2（四件套，    │
│ fail_on_unmatched_files 双保险；仅 refs/tags/v* 实际发布）                        │
│ 任一前置 job 失败 → 本 job 不执行 → 四件套无法落 Release = 硬阻断（P1 §3.3）      │
└─────────────────────────────────────────────────────────────────────────────────┘
```

- **产物流**：`snapshot` artifact = 发布四件套中的两件（tar.gz + manifest.json），tar.gz 发布前禁止任何二次处理（P2a §5.2-2）；gradle 仅消费复制，不改字节。
- **版本联动**：snapshotVersion = 构建日 UTC + oc<OC_VERSION>（build-snapshot.sh 口径）；APK versionName = tag 去 `v` 前缀（versionCode = major×10⁶+minor×10³+patch）；OC_VERSION 在 release.yml env 与 build-snapshot.sh 默认值两处同步维护，gate ③ 双向断言防漂移。

## 2. 四大 CI gate 逐项说明（任一失败即阻断）

| Gate | 校验什么 | 怎么失败 | 失败输出（日志定位） |
|------|----------|----------|----------------------|
| ① 16KB 对齐（job_android） | jniLibs 两库 + APK 解包产物：所有 LOAD 段 Align ≥ 0x4000，且 `lib*.so` 命名（C3 第 1/2 项） | 调用 `native/check-page-align.sh`（READELF 指定 NDK llvm-readelf），任一段不达标/解析不到 LOAD 段 exit 1 | `[FAIL] LOAD 段 offset=… Align=… (…)< 16384`；步骤名 `Gate 1` / `Gate 1b` |
| ② 快照体积（job_snapshot） | tar.gz ≤ 160MiB = 167772160 字节（P2a §1.4 定稿口径，严格大于即 fail） | 独立 step 重算 `stat -c%s` 比对；与 build-snapshot.sh 内置门禁同口径双保险 | `::error::快照超体积门禁 N > 167772160 字节。先裁工具链 (P2a §1.3 优先级)`；步骤名 `Gate 2` |
| ③ manifest（job_snapshot） | schemaVersion==1、snapshotVersion 格式、ocVersion==OC_VERSION、file/format/layout/excludes/minAppVersion、sha256 与 size 与实际文件一致（C1 全字段） | jq -e 断言链 + sha256sum/stat 重算比对，任一不过 exit 1 | `::error::manifest.json 未通过 C1 字段完整性断言 (P1 §3.1)` 或 `sha256/size 不一致`；步骤名 `Gate 3` |
| ④ extractNativeLibs（job_android） | full/lite 每个 APK 的 AndroidManifest 中 `android:extractNativeLibs="true"`（= gradle useLegacyPackaging=true，D4/C3 第 4 项） | aapt2 dump xmltree 后 grep 属性值非 `"true"`（含属性缺失）exit 1 | `::error::gate 4 FAIL: <apk> manifest extractNativeLibs != true (D4: …全链路不可用)`；步骤名 `Gate 4` |

另有一个**发布阻断前置**（非 P1 四 gate 之一）：`Release blocker: third-party SHA256 must be configured` —— 检出 build-qemu-user-static.sh 中 ZLIB/LIBICONV/PCRE2/GLIB 四个 `*_SHA256` 仍为空默认值即拒绝构建发布（P2b §7-1 不可发布状态，见 §6）。

## 3. Secrets 清单与签名流程

| Secret | 内容 | 用途 |
|--------|------|------|
| `KEYSTORE_BASE64` | release keystore 的 base64 全文 | CI 内 `base64 -d` 还原到 `${RUNNER_TEMP}/release.keystore`（不落工作区，runner 结束即回收） |
| `KEYSTORE_PASSWORD` | keystore 口令 | → `CI_KEYSTORE_PASSWORD` |
| `KEY_ALIAS` | 签名 key 别名 | → `CI_KEY_ALIAS` |
| `KEY_PASSWORD` | key 口令 | → `CI_KEY_PASSWORD` |

**流程**：Secrets 还原 → 以 `CI_KEYSTORE_*` 环境变量交给 build.gradle.kts 的 signingConfigs（部分缺失配置期直接报错）→ gradle 出双变体签名 APK。**纪律**：① 密钥严禁入库，keystore 原件由主理人线下保管并另备离线副本；② tag 发布时 Secrets 缺失 = 硬失败（拒绝产出不可发布物）；③ workflow_dispatch 冒烟允许回落 debug 签名（gradle `debug` signingConfig 兜底，产物打 `debug-signed` 标记且发布 assert 拒发）；④ 本地开发无需 Secrets：直接 `./gradlew assembleFullRelease`（full 需先放快照资产，lite 免）即 debug 签名侧载冒烟。日志中 Secret 值由 Actions 自动掩码，四件套 assert 末步对 debug 签名产物强制拒发。

## 4. full/lite 打包差异与产物四件套校验清单

| 维度 | full | lite |
|------|------|------|
| 快照分发 | 内嵌 `src/full/assets/snapshot/{oc-ubuntu-arm64.tar.gz, manifest.json}`（CI 注入） | 不内嵌，首启按 manifest 下载（minAppVersion 校验归 UI/引擎层） |
| 构建期防呆 | `validateFullSnapshotAssets`：资产缺失 fail-fast（挂接 mergeFullAssets） | 无资产依赖，本地冒烟首选 |
| applicationId | `dev.opencode.mobile`（同 id，不并行安装） | 同左 |

**四件套校验清单（`Assert release bundle` step，全部通过才进 Publish）**：
1. full/release 恰有 1 个 APK；2. lite/release 恰有 1 个 APK；3. 四个文件均存在且非空（full APK / lite APK / `oc-ubuntu-arm64.tar.gz` / `manifest.json`）；4. artifact 跨 job 传输后 sha256 仍与 manifest 一致（P2a §3.2 三点链路的发布前复核点）；5. manifest.ocVersion == OC_VERSION（版本联动复核）；6. 非 debug 签名。`fail_on_unmatched_files: true` 与本 assert 构成发布双保险；Publish 仅在 `refs/tags/v*` 触发。

## 5. GPL-2.0+ 与第三方许可展示页实现要求

法务口径 = P1 §8.1 勘误（proot MIT→GPL-2.0+）：随发布物保留许可证全文、标注上游来源、App 内完整展示、不得剥离/替换/隐匿。

**落地分工**：
- **release-ops（本文件）**：出包不裁剪任何 LICENSE/NOTICE；About 页数据源以 `app/src/main/assets/licenses/` 随包分发（仓库内置，入仓清单见下表），发布前核对表内版本号/仓库地址与 native 脚本锁定值一致（proot v5.1.107.96 / qemu v9.2.0，qemu 产物 `--version` 含 `OpenCode-Android-v9.2.0` 可交叉核）。
- **ui-layer**：设置页底部入口「关于 / 开源许可」→ About 页（许可清单）→ 详情页全文滚动渲染 assets/licenses 下对应文件；每条目含组件名、许可证名、版本、上游仓库链接。

**About 页必列清单（按 P2b §7-2 勘误后口径）**：

| 组件 | 许可证 | 版本 | 来源 |
|------|--------|------|------|
| proot（libproot.so，含静态依赖 talloc LGPL-2.1+ / libandroid-shmem BSD-3-Clause） | **GPL-2.0+**（随包附 GPL-2.0 全文） | v5.1.107.96 | github.com/termux/proot（上游 github.com/proot-me/PRoot） |
| qemu-user（libqemu_aarch64.so，静态依赖 zlib/libiconv/pcre2/glib 随其整体分发） | **GPL-2.0+**（qemu 主体 GPLv2，个别文件 BSD/MIT；随包附 GPL-2.0 全文） | v9.2.0 | github.com/qemu/qemu |
| opencode | 待实核（见 §8-3；初版按 MIT 展示） | 1.18.34 | github.com/anomalyco/opencode |
| ConnectBot terminal fork（M1 接入时追加） | Apache-2.0 | — | 按 D6 fork 仓库 |

`assets/licenses/` 应含：`LICENSE.proot.txt`（GPL-2.0 全文）、`LICENSE.qemu.txt`（GPL-2.0 全文 + BSD/MIT 例外文件清单）、`LICENSE.opencode.txt`、`THIRD-PARTY.md`（上表全文）。GPL-2.0+ 不传染 App 层代码（proot/qemu 为独立二进制、进程隔离，P1 §8.1 评估结论），但上述四项展示义务不可豁免。

## 7. 给 device-validator 的移交

**① CI 冒烟入口**：`workflow_dispatch` 手动触发 release 流水线（无 tag → APK 版本号回落 `0.0.0-local`）；无签名 Secrets 时按 debug 签名兜底出包（`::warning` 标记），从 run 的 artifact/产物目录取 full/lite APK 直接侧载。`snapshot` artifact 可单独下载用于 M0-5/M3-1 的下载源与哈希核对。

**② 16KB 模拟器 job（C3 第 3 项，主理人终裁 #4：已启用为 CI 硬性校验并纳入发布阻断）**：`job_smoke_16kb` 已实际启用（needs: [job_android]，ubuntu-latest x86 + KVM，API 35 16k 镜像 `x86_64-16k` 变体，headless 参数）：等待 `sys.boot_completed` → 断言 `adb shell getconf PAGESIZE` = 16384（镜像装错即在此拦截）→ adb install full APK（artifact `apks`）→ 按 P2b §3.3 执行 `adb shell "/data/app/*/lib/arm64/libproot.so --version"` 退出码 0（同时验证 D4 解包 + 16KB 内核加载 + NEEDED=0 运行时等价）。M0-3 的 qemu 模式项（guest 内 `opencode --version`）待 device-validator 交付 `native/ci-smoke-16kb.sh` 后，用 `script: bash native/ci-smoke-16kb.sh` 替换 emulator-runner 内联 script 即可挂入（TODO 已标注于 release.yml）。已知边界：full APK 为 arm64-v8a 单 ABI、16k 镜像为 x86_64 变体，若 install 报 NO_MATCHING_ABIS 属 ABI 口径问题，由 device-validator M0 矩阵裁定（真机 arm64 为最终验收口径）。**硬阻断链路**：本 job 失败 → `job_release`（needs: [job_android, job_smoke_16kb]，自 job_android 迁出的 Release 发布 + contents:write）不执行 → 四件套无法落 Release（P1 §3.3）。

**③ 用 CI 日志核四大 gate 生效（M3-4/M3-5 演练矩阵）**：

| 演练注入 | 预期失败点 | 预期日志特征 |
|----------|-----------|--------------|
| 注入 4KB 对齐库（默认 flag 重编 proot 替换 jniLibs） | Gate 1 | `[FAIL] LOAD 段 … < 16384` |
| 把 tar.gz 追加随机字节超 160MiB | Gate 2（脚本内门禁先拦） | `::error::快照超体积门禁` |
| 手改 manifest 任意字段 / 篡改 tar.gz | Gate 3 | `未通过 C1 字段完整性断言` 或 `sha256 不一致` |
| gradle 注释掉 useLegacyPackaging | Gate 4 | `manifest extractNativeLibs != true` |
| 删掉任一发布产物 | Assert release bundle | `::error::发布产物缺失或为空` |

各 gate 的 PASS 侧日志同样可核：Gate 1 输出 `[PASS] N 个 LOAD 段全部 Align >= 0x4000`、Gate 2 输出 `snapshot size = … bytes (gate = …)`、Gate 3 输出 `gate 3 PASS: oc=… sha256=… size=…`。CI 绿 + 上述 PASS 行齐全 = 四大 gate 实际生效（而非仅步骤存在）。
